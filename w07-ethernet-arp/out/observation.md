# Task 1 · 학습 스위치

목적지 포트가 수신 포트와 같으면 보내지 않도록 했다. 이미 프레임이 온 쪽에 목적지가 있으므로 다시 보내면 같은 구간에 불필요한 트래픽만 생긴다.
스위치는 목적지를 몰라도 다른 포트로 보내 같은 LAN 안에서 찾을 수 있다. 라우터는 기본 경로를 포함해 맞는 경로가 없으면 보낼 다음 홉을 정할 수 없어 버린다.
B가 2번에서 3번 포트로 옮겨가자 테이블도 바뀌었고, 400초 뒤에는 오래된 A 항목이 지워졌다. 다만 시간만으로는 떠난 장치와 조용히 있는 장치를 구분하지 못한다. 직접 응답을 확인하면 더 분명하겠지만 별도 통신이 필요하다.

# Task 2 · ARP 관찰

캐시를 비운 뒤 확인하니 게이트웨이 192.168.219.1이 먼저 돌아와 있었고, 동적 항목은 2개에서 1개로 줄었다. 외부 통신에 공유기 주소가 필요하고, 이전의 다른 장치 항목은 다시 학습되지 않은 것으로 보인다. ping 전부터 복원돼 있어 백그라운드 통신도 영향을 줬을 수 있다. 접속한 웹 서버는 ARP 테이블에 없었는데, 외부로 보낼 때는 서버가 아닌 게이트웨이의 MAC 주소를 쓰기 때문이다.
내 PC가 보낸 요청의 목적지는 ff:ff:ff:ff:ff:ff, 공유기 응답의 목적지는 내 PC의 8c:17:59:ac:3b:cc였다. 요청은 같은 네트워크에 널리 묻고, 응답은 요청한 PC로 돌아오는 차이를 확인했다.
1분 동안 ARP 139개가 잡혔다. 1,000대로 가정하면 139,000개/분이지만, 같은 브로드캐스트가 여러 PC에 보이므로 실제 발생량과 같지는 않다. 공개 캡처에는 내 PC 관련 4개만 남겼고, 139개는 원본에서 센 값이다.
