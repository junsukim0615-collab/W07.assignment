# Task 3 비교 분석

48개 포트, 400개 장치, 테이블 용량 64개 조건에서 제공된 bench.py를 수정하지 않고 실행했다. 실제 생성된 프레임은 48,954개였다.

| 방식 | 불필요한 전달 | 정상 전달 | 누락 |
|---|---:|---:|---:|
| 기존 FIFO | 323,380 | 46,347 | 0 |
| 빈도 기반 교체, 새 출발지 항상 수용 | 158,056 | 46,347 | 0 |
| 빈도 기반 교체, 선택적 수용 | 156,814 | 46,347 | 0 |

최종 감소율은 약 51.51%로 strong 기준인 45% 이상을 충족했다. 선택적 수용은 항상 수용하는 버전보다 불필요한 전달을 1,242회 더 줄였다. 이 비교는 메모리에서 수용 조건만 항상 참으로 바꾼 별도 클래스로 수행했으며 제출 코드와 bench.py는 변경하지 않았다.

## 구현 방식

이미 관측한 프레임의 출발지·목적지 등장 횟수를 센다. 테이블이 가득 차면 빈도가 가장 낮은 항목을 교체 후보로 삼고, 동률이면 최근 사용 시각이 오래된 항목을 고른다. 새 출발지의 빈도가 후보보다 높을 때만 새 항목을 받아들인다. 등록된 출발지는 다시 나타날 때 포트를 갱신한다.

MAC→포트 매핑은 table에만 저장하며 용량은 64개를 넘지 않는다. 빈도 기록은 최대 capacity×8개로 제한하고 포트 정보는 저장하지 않는다. 미래 프레임이나 정답 위치 where는 사용하지 않는다. 목적지를 모르면 수신 포트를 제외하고 flooding하므로 학습을 거절해도 전달 기회는 유지된다.

## 검증과 한계

제공된 Task 3 검사에서 성능·누락 검사 2개를 통과했고 실패는 없었다. 용량 제한은 매 프레임 검사된다. 공격 설명은 사람이 평가하는 항목이라 자동 검사에서 skip으로 표시된다.

이번 결과는 기본 seed의 트래픽에 대한 결과다. 누적 빈도를 사용하므로 인기 장치가 갑자기 바뀌면 예전 장치를 오래 유지할 수 있다. 일정 주기마다 빈도를 줄이는 방식은 추가 개선 방향이다.
